# Pair Dev

ユーザーは動いているアプリを見て指摘し、あなたが作業する。時間のかかる仕事は裏で進めて、次の指摘へ進む。

## 始める

ほかの worktree とぶつからないようにアプリをローカルで起動し、ユーザーも見られる**共有の画面**で開く。共有の画面は、ブラウザのタブ、シミュレーター、エミュレーター、ウィンドウなどで、ターミナルマルチプレクサのペインで開くか、自動操作のツールで動かす。表示を確かめたら、気になるところを尋ねる。作業は自分の画面で行い、ユーザーの画面には触らない。

## 指摘ごとに

- **「Issue にして」**: いまの動きと直したあとの動きを書いて Issue にする。
- **「ここを直して」**: 最新の既定ブランチから、話題ごとにブランチを切る。ユーザーに尋ねるのは、ユーザーが決めるべき設計の選択だけにする。リポジトリの決まりに従って直し、結果を報告する。
- **答えが一つに決まらない選択**: コードを変える前に、ユーザーが開けるページ（Artifact）に案を並べ、おすすめを添える。案は実寸で、変更が届くすべての画面で描く。選ばれた案を作る。
- **「PR して」**: PR を出し、CI と Preview の監視と結果報告を委任先に任せ、次の指摘へ戻る。
- **同じ問題がコードベースのあちこちにある**: 目の前の箇所だけ直し、残りは横展開として提案する。

## マージの許可

対象の PR のマージをユーザーが明示的に依頼した場合だけマージする。PR 作成の依頼が許可するのは、作成と CI/Preview の監視まで。スキルの起動、チェックの成功、「最後までやって」などの曖昧な完了指示は、マージや自動マージの有効化を許可しない。明示的なマージ許可がなければ、PR を開いたまま状態を報告する。

## 委任する

委任先にはいつも、専用の worktree、止まって報告する条件、報告に使う言語（ユーザーの言語）を渡す。委任先のマージ権限も明記する。既定では監視のみとし、マージできるのはユーザーが明示的に依頼した対象の PR だけ。委任によって権限を広げない。委任先からの報告はユーザーに伝え、判断が要る点は選択肢にする。

- **CI と Preview の監視**: サブエージェントが CI と Preview を待ち、結果や失敗を報告し、PR を開いたままにする。
- **明示的に依頼されたマージ**: サブエージェントはチェックが通ったあと、許可された PR だけを指定の順にマージできる。失敗やマージにユーザーの判断が要るときは止まる。
- **調査**: サブエージェントが失敗の根本原因を突き止める。直す範囲が小さく、直し方がはっきりしているときだけ直し、そうでなければ選択肢とおすすめを報告する。
- **横展開**: 別のコーディングエージェントが、専用の worktree とマルチプレクサのペインで、コードベース全体に同じ変更を入れる。その計画を承認したら、PR を出すまで任せる。
